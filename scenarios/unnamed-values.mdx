## Walkthrough

1. Select **Auto Parser**, paste the complete sample and choose **Analyze Logs**.
2. Confirm **1 of 1 log event parsed completely**; this does not prove the meaning of every positional CSV column.
3. Review the source CSV against the [official PAN-OS field definitions](https://docs.paloaltonetworks.com/ngfw/help/12-2/syslog-field-descriptions).
4. Use the PAN-OS field reference to confirm the CSV delimiter and field positions; the reported Link Switches field contains embedded commas.
5. If a column-name review appears, only confirm names backed by the correct vendor definition and CSV grouping.
6. Preserve neutral source column names if possible when semantic meanings are uncertain; never force a mapping from one example.
7. Compare the original Link Switches group including commas, then use **Map Fields** to review only evidence-backed destinations.
8. Continue to **Create Parser** only after independent schema and field-meaning verification. This sample does not certify live PAN-OS compatibility.

## Expected review outcome

The real PAN-OS issue record returned **1 of 1 log event parsed completely** in the public UI, but this is structural success, not proof that every comma-separated column has the correct meaning. Source-backed names are used only if you actually confirmed what they mean.

## Recovery path

If the column count changes between rows, stop. Some logs from the same product have different shapes. Follow [the multiple-log-types guide](/scenarios/mixed-events) instead of stretching one column definition over every row.

<Warning>
  A field named `field_001` is intentionally neutral. Do not label it "timestamp" merely because a sample value looks like a date unless the source definition supports that interpretation.
</Warning>
