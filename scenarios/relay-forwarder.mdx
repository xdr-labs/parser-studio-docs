# Hands-on: FortiGate Traffic logs forwarded through rsyslog

This scenario uses **real FortiGate Traffic and Web Filter example records published by Fortinet**, not fabricated firewall events. We submitted those unchanged messages over **UDP to an actual `rsyslogd` input**, configured `rsyslogd` to forward them with a new RFC3164 header, and captured the **UDP output bytes**. Paste that *captured post-relay output* below into Parser Studio: this is the exact input used to test the page.

<Note>
**Source versus transport evidence:** The security-event bodies are published vendor samples from [Fortinet's official log examples](https://docs.fortinet.com/document/fortigate/6.2.0/cookbook/986892/sample-logs-by-log-type). The **outer `relay01` header is not FortiGate output**: it is the real output of a separately launched rsyslogd on the lab server. The packet capture is not from a production network or live FortiGate appliance. All original vendor-message bytes were checked unchanged after forwarding. Parser Studio product reference: [main a4b4e2f](https://github.com/xdr-labs/parser-studio/commit/a4b4e2fba54588fa2b9807e1cfeed49190061927).
</Note>

## Walkthrough

1. Open [Parser Studio](https://app.parser.xdr.ooo/) and select **Auto Parser**. Fill **Manufacturer** = `Fortinet`, **Product** = `FortiGate`; no firmware version is inferred from the example lines. Leave the proposed .conf listener port at **6801**.
2. Paste **both full lines** from **Section 2**, including the `<134>` Syslog prefix, into **Add Logs**. Alternatively, upload `05-relay-forwarded.log`. Do not manually remove any prefix or values.
3. Expand **Optional: declare Syslog forwarder hostnames**. Set **Relay hostnames (comma-separated)** to `relay01` and **Maximum declared hops** to `1`.
4. Verify **Relay source preview** says **2 of 2 events recognized, 0 unsafe and 0 not matching a declared relay**; click **Apply declared relay profile**.
5. Click **Analyze Logs**. With this exact captured source, the observed result was **2 of 2 log events parsed completely**. If anything differs, inspect the source instead of deleting records.
6. Click **Review Fields**. Check `srcip`, `dstip`, `action`, `proto`, `sessionid` from the *FortiGate body* against the original text. Continue to **Map Fields** and verify the selected Stellar Cyber 7.0 mapping.
7. Continue to **Create Parser**, then click **Run Final Test & Create Files** only if enabled. The live browser exercise for these source records reached Review Fields; generated parser deployment and actual Stellar Cyber receiver compatibility are separate checks.

## How this capture was produced

The lab used `rsyslogd 8.2312.0`, independently launched with `imudp` input and `omfwd` UDP output, on loopback-only ephemeral ports. Its custom output template added `<134>`, `relay01`, `forwarder:` and a timestamp while writing `%rawmsg%` to preserve the original vendor payload. **3/3 payloads were byte-identical to the official source lines**. We did not use a Python function to fabricate the Syslog headers.

If you want to reproduce the UDP path on a disposable, authorized Ubuntu lab, download the vendor input files and [capture script](https://raw.githubusercontent.com/xdr-labs/parser-studio-docs/main/practice/capture_with_rsyslog.py), and run it there with the required permissions. The script creates a standalone process without restarting the system rsyslog service. It is **not** a production deployment runbook.

## Expected review outcome

In the real public Web UI: **2/2** forwarded Traffic events recognized and fully parsed, plus **1/1** different Web Filter forwarded holdout recognized and fully parsed. Independent target reception, generated artifact native compatibility, and operation on a real FortiGate-to-DP network remain **not verified**.

## Recovery path

If the outer header is not recognized, check the exact relay hostname and <escape><</escape>PRI<escape>></escape> framing. **Optional: mark a forwarded prefix or trailing suffix** only reviews fixed literal text; it does not configure native conditional unwrapping of changing timestamps. For incomplete events, preserve **Text not yet assigned to fields** and re-test with additional authentic vendor samples.
