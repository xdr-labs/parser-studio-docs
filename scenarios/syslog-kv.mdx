# My logs start with a timestamp and device name

**Situation:** Every log begins with characters such as `<134>`, a timestamp, host name and message text. You may not know what these mean. **Paste the full log anyway**, including the beginning.

## Practice sample

```text
<134>Oct 18 12:00:00 edge-fw firewall: action=deny src=192.0.2.21 dst=198.51.100.24 dport=22 user="demo admin"
<134>Oct 18 12:00:01 edge-fw firewall: action=allow src=192.0.2.22 dst=198.51.100.25 dport=443 user="demo user"
```

## Walkthrough

1. In **Auto Parser → Add Logs**, paste both lines exactly. **Do not remove** the leading number, device name or the quotes around the user.
2. Click **Analyze Logs**.
3. If both events parse completely, select **Review Fields**.
4. Compare Event 1 and Event 2. Check that each action, address, port and quoted username is a complete value.
5. If a timestamp or header warning is shown, select the flagged event under **Problem to review** and read **What needs attention**. The header may not contain all date/time details.
6. When the source is completely reviewed, proceed to **Map Fields**, confirm field destinations, and run the final test.

## Expected review outcome

Each line counts as one event; the leading header remains distinct from message fields; `demo admin` stays one user value.

## Recovery path

When the app flags the header/time, do not invent a timezone or year just to make the warning disappear. Obtain the original source's time information or follow the offered reviewed handling. For an incorrectly split quoted string, use [the partial-event guide](/scenarios/partial-event).

<Note>
  The source above resembles traditional Syslog with key/value fields, but recognizing the name is **not** a prerequisite for using Parser Studio.
</Note>
