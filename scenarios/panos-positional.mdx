# My firewall log is a very long comma-separated line

**Situation:** You paste what may be a Palo Alto Networks-style traffic or threat event. The record contains many values, and the product may send different event types.

## Practice example

```text
1,2026/10/18 12:00:00,000001,TRAFFIC,end,192.0.2.10,198.51.100.20,allow
```

This is an **abbreviated fictional teaching line**, not a real firmware-specific field specification.

## Walkthrough

1. In **Auto Parser**, paste a few complete logs from **one known source/event type** first. Click **Analyze Logs**.
2. If the UI says the positions need names, look for **Names to give each value** and **Character between the values**.
3. Obtain the vendor log definition for the same product/firmware and event subtype. Enter exactly the listed field names **in order**.
4. If that definition is unavailable, use **Keep all values with temporary names** to avoid guessing.
5. Choose **Review Fields** only after the column review is accepted. Switch between example events and ensure missing or empty values have not shifted adjacent columns.
6. In **Map Fields**, assign destinations only where the source field meaning is established. Retain uncertain values as vendor-specific fields.
7. Run the final test and download only if the app supports the reviewed event shape.

## Expected review outcome

The position and name of every value is based on the actual source definition—or remains visibly neutral when unknown.

## Recovery path

If **TRAFFIC**, **THREAT** and other rows have different lengths, do not force them into one positional layout. Paste representative examples of each type and follow [the several-types scenario](/scenarios/mixed-events).
