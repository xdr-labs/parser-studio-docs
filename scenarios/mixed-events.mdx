# My security product produces several kinds of events

**Watch:** [English tutorial using published real log samples](/videos/multiple-types).

**Situation:** One security product generates traffic, threat, authentication and other events. You want to support all of them rather than create a parser that works with only the first example.

Begin in **Auto Parser**. You do not have to choose a log format or create a separate parser before examining the records.

## Practice with published FortiGate samples

- [Traffic logs: two original events](https://app.parser.xdr.ooo/training/parser-studio-real-scenarios-20261021/practice/04-fortigate-traffic.log).
- [Threat logs: web filter and IPS](https://app.parser.xdr.ooo/training/parser-studio-real-scenarios-20261021/practice/04-fortigate-threat.log).
- [Watch the current Web UI walkthrough](/videos/multiple-types).

## Walkthrough

1. Open **Auto Parser** and enter Fortinet / FortiGate.
2. Choose **Add Another Log Type** to create **Traffic** and **Threat** groups.
3. Paste the two original traffic events in Traffic and the web filter/IPS records in Threat. Do not invent a combined log format.
4. Choose **Analyze Logs**. The published four-event source sample reports **4 of 4 events parsed completely**.
5. Open **Review Fields**. Inspect the actual source **type/subtype** values and verify the webfilter and traffic samples' shared **sessionid 381780**.
6. Inspect the **Optional: one parser for several event types** review when needed. Labels alone do not create a verified discriminator.
7. Review Stellar Cyber **7.0** mappings and test **all four samples** under Create Parser before downloading the package.

## What if some event types are not recognized?

If **Different log shapes were found** appears, follow the offered **Analyze group 1 · N similar events** action for each group.

1. Review the first selected group and, if supported, create a draft for that group.
2. Use **Return to all N logs** to restore the complete original input.
3. Review the other groups. **Do not claim a single combined parser** unless the final generation stage verifies that exact combination.

For a small unresolved fragment, use [the partial-event guide](/scenarios/partial-event). If the structure remains completely unfamiliar, follow [ChatGPT Assisted Parser](/scenarios/unknown-log).

## Expected review outcome

Every event from the submitted sample is accounted for. The review preserves event-specific fields without assigning the wrong type or meaning. A single combined draft is reported only when its validation succeeds.

## Recovery path

If the next-step button remains unavailable, check **Must fix before continuing** and read the field-level findings. Correct the failing destination or type. If different source shapes cannot be safely combined, review separate source groups without dropping original events.
