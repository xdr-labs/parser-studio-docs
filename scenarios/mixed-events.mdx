# One security product sends traffic, threat, user and other logs

**Situation:** A single firewall or security platform sends several kinds of events. You want **one parser if the shapes can safely be combined**, but you do not want events to disappear from the analysis.

**You do not have to separate CEF, LEEF, JSON and KV by name before you start.**

## First try: paste the event types together

Collect at least one complete example of **each event type** you expect to support. More variation helps reveal missing or optional fields. For a fictional practice feed:

```text
{"action":"allow","src_ip":"198.51.100.10","dst_port":443}
src_ip=203.0.113.11 dst_port=22 action=deny
CEF:0|Synthetic|Firewall|1|101|Denied|8|src=192.0.2.11 dpt=443 act=deny
LEEF:1.0|Synthetic|Firewall|1|501|src=192.0.2.18	dstPort=80	act=allow
```

This practice input uses **four structurally different events**. In real use, keep all original log events intact.

*The real UI analyzed the four fictional records together. The user did not choose their formats first.*

## Walkthrough: attempt one combined parser

1. Open **Auto Parser → Add Logs**. Enter the manufacturer/product identity for this source.
2. Paste **all representative event types together** and click **Analyze Logs**.
3. Check the count: if the input has 20 source events, all 20 should be accounted for. The format labels are secondary to this complete accounting.
4. If all events are parsed, click **Review Fields** and switch between events from **different types**, not just different values of one type.
5. Click **Map Fields**. For each distinct field, confirm the output destination and data type. A field may be absent in one event type; absence is not automatically a parser error.
6. Confirm **Must fix before continuing = 0**, then click **Create Parser**.
7. Choose **Run Final Test & Create Files**. A **single combined parser draft** is available only when the generator accepts that particular reviewed combination.

*Different source shapes can share one reviewed project, but inspect fields that are not present in every event.*

## What if the analysis finds several groups instead?

If the page shows **Different log shapes were found** and buttons such as **Analyze group 1 · N similar events**:

1. Click **Analyze group 1**.
2. Review the resulting subset and create a separate parser draft **for that group only** if supported.
3. Click **Return to all N logs** to recover the full original sample.
4. Analyze the next group. Do not assume that separate group drafts have been automatically merged.

The product preserves the other groups. A complete multi-group review is not evidence that one combined output file was created.

## Expected review outcome

All original source events are counted. You either obtain one validated, supported mixed parser draft or distinct reviewed parser drafts for incompatible shapes. No event is silently discarded merely because it was difficult.

## Recovery path

If one type is flagged, select it under **Problem to review** and use the recommended repair. Do not remove unsupported messages just to get a green result. When a real product uses multiple positional CSV layouts, first obtain the matching field order for each layout before attempting a combined draft.
