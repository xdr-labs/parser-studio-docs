# My log contains vertical bars or many field separators

**Situation:** The product log includes `|`, `=`, or TAB separators. It may be an event format used by many security products. You don't need to know which one.

## Practice samples

**Example A**

```text
CEF:0|Example Vendor|Security Gateway|1.0|1001|Denied connection|6|src=192.0.2.10 dst=198.51.100.21 dpt=443 act=blocked suser=demo
```

**Example B — actual TAB characters between extension values**

```text
LEEF:1.0|Example Vendor|Security Gateway|1.0|1001|src=192.0.2.10	dst=198.51.100.21	dstPort=443	action=blocked
```

## Walkthrough

1. Copy several real events from your own product and paste them in **Auto Parser → Add Logs**. Keep the original separators and escape characters.
2. Click **Analyze Logs**. If the entire sample is complete, click **Review Fields**.
3. Pick two different events. Confirm the event name, action, address and port are attached to the correct source fields.
4. Click **Map Fields** and review destination mappings before **Create Parser**.
5. If a field ends too early or two fields have been joined together, return to the flagged event and open **Recommended fix** rather than manually deleting separators.
6. Download files only after the sample and mapping checks pass.

## Expected review outcome

The fixed header and event-specific fields are separated correctly; the original values are preserved.

## Recovery path

If a source value contains a literal delimiter or an unusual escape rule, keep that exact source evidence. Use [the partial-event repair](/scenarios/partial-event) and validate any proposed change against more samples.
