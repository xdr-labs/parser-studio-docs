# Auto Parser cannot handle a field. Ask ChatGPT for help.

**Situation:** You used **Analyze Logs**, but a text fragment was highlighted, or the original field was not extracted completely.

## Example to practice with

```text
date=2026-10-18 action="policy denied" src=192.0.2.10 reason="destination not authorized"
date=2026-10-18 action="policy allowed" src=192.0.2.11 reason="trusted network"
```

Suppose the value of `reason` is incomplete. Do not throw away the working `action` and `src` fields.

## Walkthrough

1. In **Auto Parser → Add Logs**, paste the sample and choose **Analyze Logs**.
2. If the event needs review, read **Original event**, the highlighted text, and **Recommended fix**.
3. Choose **Fix with ChatGPT** or **ChatGPT Assisted Parser** from the left.
4. In **Original local logs**, retain the original events for local testing.
5. In **What do you want Parser Studio to find?**, enter a specific goal: “Preserve the complete values of action and reason, including quoted spaces, without changing source addresses.”
6. In **Redacted example to copy to ChatGPT**, confirm that every value is fictional or properly masked.
7. Click **Prepare ChatGPT Prompt**, review it under **2. Copy to ChatGPT**, and click **Copy Prompt**.
8. Open ChatGPT manually and ask for a JSON response using the requested **ParserRecipe v0.2** contract.
9. Paste the result under **3. Paste the ChatGPT result** and click **Check ChatGPT Result**.
10. If a changed rule requires independent samples, supply different fictional or masked records under **Additional ChatGPT test logs**, review the comparison, and approve only a passing change.

## Expected review outcome

A supported proposal recovers the intended field without breaking values that were already correct. The change is tested rather than blindly executed.

## Recovery path

If ChatGPT returns executable code instead of the requested JSON, or a rule that Parser Studio rejects, request a narrower supported change. If different test logs fail, do not approve it.
