# Review Fields에서 값이 맞는지 확인하기

파싱 상태가 녹색이라는 것만으로 충분하지 않습니다. 원본 값이 올바른 필드에 들어갔는지 비교해야 합니다.

![Review Fields에서 원본·추출값·출력을 비교하는 화면](/images/current-03-review-fields.png)

## 확인 순서

1. **Choose a source event**에서 Event 1, Event 2 등을 바꿉니다.
2. **Original log**의 주소·사용자·액션·포트를 확인합니다.
3. **Fields Parser Studio found**에서 원본의 각 값이 올바르게 분리되었는지 확인합니다.
4. **Current output preview**에서 필요한 값이 출력에 남아 있는지 확인합니다.
5. 잘못 연결된 목적지 필드명은 **Map Fields**에서 수정합니다. 추출 자체가 잘못됐다면 **Need a different extraction? Fix a field with ChatGPT**를 검토합니다.

## 다른 로그 유형이 있을 때

여러 유형의 샘플을 추가했다면 **Review fields by the log types you entered**의 유형별 출처 목록을 확인합니다. 같은 이벤트에 없는 선택적 필드는 임의의 값으로 채우지 않습니다. **Optional: one parser for several event types**에서는 실제 존재하는 구분 필드만 검토합니다.

## 복잡한 로그의 잔여 텍스트

Auto Parser 진단의 **Text not yet assigned to fields**는 아직 매핑되지 않은 원본 범위를 뜻합니다. **Values already found**의 기존 값은 유지하면서 해당 영역만 검토하고, 규칙 변경 후 다른 예시를 테스트합니다.
