# 실습: FortiGate 공식 보안 로그를 실제 rsyslog로 전달하고 파싱하기

이 실습은 **Fortinet에서 공개한 실제 FortiGate Traffic 및 Web Filter 로그 예제**를 사용합니다. 가상 방화벽 이벤트를 만들어 넣은 것이 아닙니다. 실제 `rsyslogd` 프로세스에 원문을 UDP로 전달하고, 릴레이가 Syslog 헤더를 추가하여 다시 전송한 **실제 UDP 수신 내용**을 캡처했습니다. 아래 로그를 그대로 복사해서 Parser Studio에 붙여 넣으면 됩니다.

<Note>
**출처와 전달 환경을 구분하세요.** 보안 이벤트 본문은 [Fortinet 공식 Sample logs by log type](https://docs.fortinet.com/document/fortigate/6.2.0/cookbook/986892/sample-logs-by-log-type)의 공개 예제이고, 바깥쪽 `relay01` 헤더는 **테스트 서버에서 실제 rsyslog가 생성**한 것입니다. 운영 중인 FortiGate 장비·고객 네트워크를 캡처했다고 주장하지 않습니다. 원본 이벤트의 모든 바이트가 릴레이 후에도 보존되는지 확인했습니다. 테스트 제품 기준: [main a4b4e2f](https://github.com/xdr-labs/parser-studio/commit/a4b4e2fba54588fa2b9807e1cfeed49190061927).
</Note>

## 2. 릴레이 후: 실제 rsyslog UDP 수신 로그 두 건 — 이 부분을 복사하세요

실제 `rsyslogd`가 `omfwd`를 통해 송신하고 수신 소켓이 확보한 원문입니다. 바깥쪽 Syslog 헤더의 시간은 **릴레이 수행 시각**, 내부 `date=2019-...`는 **원본 보안 이벤트 시간**입니다.

## 따라 하기

1. [Parser Studio](https://app.parser.xdr.ooo/) → **Auto Parser**를 선택하고 **Manufacturer**에 `Fortinet`, **Product**에 `FortiGate`를 입력합니다. 샘플에 없는 펌웨어 버전은 임의로 지정하지 않습니다. 기본 수신 포트는 **6801**로 둡니다.
2. **2번 절의 릴레이 전달 후 로그 두 줄 전체**를 `<134>`부터 끝까지 복사해 **Add Logs**에 입력합니다. 또는 `05-relay-forwarded.log` 파일을 업로드합니다.
3. **Optional: declare Syslog forwarder hostnames**를 열고 **Relay hostnames (comma-separated)**에 `relay01`, **Maximum declared hops**에 `1`을 입력합니다.
4. **Relay source preview**에서 **2 of 2 events recognized, 0 unsafe and 0 not matching a declared relay**를 확인한 뒤 **Apply declared relay profile**을 클릭합니다.
5. **Analyze Logs**를 눌러 **2 of 2 log events parsed completely**가 표시되는지 확인합니다. 실제 공개 UI에서 해당 결과를 확인했습니다.
6. **Review Fields**에서 원문 `srcip`, `dstip`, `action`, `proto`, `sessionid` 값을 비교합니다. 이어서 **Map Fields**에서 Stellar Cyber 7.0 매핑과 실제 값을 검토합니다.
7. **Create Parser**로 진행하고 **Run Final Test & Create Files**가 허용되면 실행합니다. 파서 파일 생성 여부와 별개로 실제 Stellar Cyber DP 설치·수신은 검증되지 않았습니다.

## 3. 별도 검증용 실제 FortiGate Web Filter 이벤트 — 처음 학습에 넣지 마세요

아래 한 줄은 **다른 유형의 Fortinet 공식 Web Filter 로그**를 실제 rsyslog로 전달해 캡처한 것입니다. 원래 Traffic 두 건의 파서 작성에 섞지 말고, **새 Auto Parser 검증**에 붙여 넣어 동일한 `relay01` 설정으로 확인합니다.

```text
<134>Oct 31 14:42:17 relay01 forwarder: date=2019-05-13 time=16:29:45 logid="0316013056" type="utm" subtype="webfilter" eventtype="ftgd_blk" level="warning" vd="vdom1" eventtime=1557790184975119738 policyid=1 sessionid=381780 srcip=10.1.100.11 srcport=44258 srcintf="port12" srcintfrole="undefined" dstip=185.244.31.158 dstport=80 dstintf="port11" dstintfrole="undefined" proto=6 service="HTTP" hostname="morrishittu.ddns.net" profile="test-webfilter" action="blocked" reqtype="direct" url="/" sentbyte=84 rcvdbyte=0 direction="outgoing" msg="URL belongs to a denied category in policy" method="domain" cat=26 catdesc="Malicious Websites" crscore=30 craction=4194304 crlevel="high"
```

실제 검증 결과는 릴레이 헤더 **1/1 인식**, 보안 이벤트 **1/1 완전 파싱**입니다. 한 개의 Web Filter 이벤트를 성공했다고 전체 FortiGate 이벤트 유형이 검증된 것은 아닙니다.

## 실제 수신 로그 생성 방법

사용한 릴레이는 `rsyslogd 8.2312.0`입니다. 독립 실행한 `imudp` 입력에서 원문을 받아 `omfwd` UDP 출력으로 다시 전송했습니다. 출력 템플릿이 `<134>`, 릴레이 호스트명 `relay01`, `forwarder:` 레이블 및 릴레이 시간을 추가했고, **`%rawmsg%`를 이용해 공식 로그 원문 3건을 바이트 단위 그대로 보존**했습니다.

재현이 꼭 필요한 경우에만 권한이 분리된 Linux 실습 서버에서 [rsyslog 캡처 스크립트](https://raw.githubusercontent.com/xdr-labs/parser-studio-docs/main/practice/capture_with_rsyslog.py)를 실행할 수 있습니다. 시스템 rsyslog 서비스를 재시작하지 않으며 운영 장비 연결을 요구하지 않습니다. 단순한 Python 문자열 접두어 시뮬레이션이 아닙니다.

## 예상 결과

공개 웹 UI 실제 테스트 결과: FortiGate Traffic **2/2 완전 파싱**, 별도 Web Filter **1/1 완전 파싱**. 실제 고객 장비의 수신·Stellar Cyber DP 수집·원어민 파서 런타임 호환성은 이번 웹 실습의 검증 범위가 아닙니다.

## 복구 방법

릴레이 헤더 인식에 실패하면 `relay01`과 Syslog `<134>` 형식을 확인하세요. **Optional: mark a forwarded prefix or trailing suffix**는 고정 문자열 범위만 검토하며, 변하는 타임스탬프까지 처리하는 파서 규칙을 자동 생성하지 않습니다. 미해석 영역이 있으면 원본을 지우지 말고 **Text not yet assigned to fields**에서 확인합니다.
