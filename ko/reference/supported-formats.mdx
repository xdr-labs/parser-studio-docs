# 어떤 로그를 넣을 수 있나요?

형식을 사용자 스스로 판별할 필요는 없습니다. **Auto Parser**에 원본 로그 몇 건을 붙여 넣고 **Analyze Logs**를 눌러 구조 인식 결과를 확인합니다.

| 원본에서 보이는 예시 | 관련 구조 | 확인할 점 |
|---|---|---|
| 중괄호로 감싼 필드·값 | JSON | 배열, 중첩 필드, 중복 키, 줄 경계 |
| srcip=192.0.2.10 action=deny | KV | 따옴표, escape, 중복 키, 빈 값 |
| CEF:0 또는 LEEF:2.0 | CEF/LEEF | 확장 필드와 delimiter 의미 |
| 날짜,IP,포트처럼 구분된 열 | CSV | 정확한 열 순서와 따옴표 문법 |
| PRI, timestamp, hostname 앞부분 | RFC 3164/5424 Syslog | 헤더/본문, 메시지 프레이밍과 타임스탬프 |
| #Fields: 등의 헤더나 Zeek TSV | W3C/Zeek | 원본 헤더, 필드 순서, 탭 구분 |
| 여러 줄의 예외 스택 | Java 등 복합 이벤트 | 논리 이벤트 경계 |

형식 인식과 **다운로드할 파서 컴파일 지원**, 실제 Fluentd 실행 및 Stellar Cyber 호환성은 서로 다른 단계입니다. 예를 들어 CSV 필드 이름이 없어도 원본 값은 추출되지만, 안전한 열 이름 지정이 필요할 수 있습니다.

## 이해되지 않는 로그라면

- **Part of this event still needs parsing**: 이미 인식한 필드와 남은 영역을 구분해 추가 검토
- **This event could not be safely structured yet**: 원본 구조나 프레이밍 점검
- **Parser files not ready**: 원본 추출은 완료됐어도 현재 생성기가 미지원인 경우
- **Values found, but this log does not include field names**: CSV의 열 이름을 검토
