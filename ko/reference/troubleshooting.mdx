# 파서를 만들 수 없거나 분석 결과가 이상한가요?

## 화면 메시지별 점검

| 실제 UI 표시 | 먼저 할 일 |
|---|---|
| Part of this event still needs parsing | Problem to review에서 미파싱 원본 영역과 Values already found 확인 |
| This event could not be safely structured yet | 원본 이벤트의 길이, 전송 형식, 프레이밍 확인 |
| Values found, but this log does not include field names | 임시 CSV 필드명 또는 신뢰할 수 있는 열 이름 입력 |
| Must fix before continuing | 잘못된 자료형, 필드 충돌, 원본/대상 매핑 해결 |
| The proposed fix did not pass | 원본 및 추가 Holdout 로그를 다시 확인하고 규칙 수정 |
| Parser files created successfully가 나타나지 않음 | 백엔드 연결/지원 여부와 Create Parser 오류 메시지 확인 |

![미파싱 영역을 표시한 실제 제품 화면](/images/current-09-unparsed-region.png)

## 이벤트가 잘못 나뉜다면

복잡한 Java 예외나 multiline 데이터는 물리적인 줄과 논리 이벤트가 다를 수 있습니다. 파일 업로드로 정확한 줄바꿈을 유지하고, 송신기가 실제로 사용하는 구분자를 확인하세요.

## 매핑만 이상하다면

Review Fields에서 원본 값이 옳고 Map Fields 대상만 잘못됐을 경우 **파싱 규칙을 다시 만들 필요가 없습니다.** 필드 대상과 타입만 수정하세요.

## ChatGPT 결과가 거부된다면

원본 식별 불일치·지원되지 않는 JSON 단계·정규식 안전성 오류·필드 손실 등의 거부는 정상적인 안전 동작입니다. 거부 이유와 마스킹한 예시로 더 좁은 규칙을 요청하고 회귀 테스트합니다.

## 수신 포트 주의

기본 CONF 수신 포트는 6801입니다. 다른 포트를 사용한다면 생성 파일과 대상 환경의 설정이 일치하는지 확인해야 합니다. Parser Studio의 브라우저에서는 실제 센서 연결/수신 성공을 검증하지 않습니다.
