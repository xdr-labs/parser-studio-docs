# 동영상 05 — FortiGate 원본 로그를 실제 rsyslog로 릴레이하기

실제 Parser Studio 웹 UI를 녹화하고, **Fortinet이 공개한 공식 Traffic 로그 두 건**을 사용했습니다. 보안 로그는 임의로 만들지 않았으며, 바깥의 Syslog 헤더는 별도로 실행한 **실제 `rsyslogd`가 UDP로 전달하면서 추가**했습니다. 따라서 운영 장비 캡처는 아니지만 실제 릴레이 출력입니다. 영어 나레이션과 화면 자막이 들어 있습니다.

## 따라 하기

1. **Manufacturer**에 `Fortinet`, **Product**에 `FortiGate`를 입력하고 위의 수신 로그 2건을 **Add Logs**에 붙여 넣습니다.
2. **Optional: declare Syslog forwarder hostnames**를 열고 릴레이 호스트 `relay01`, 최대 홉 `1`을 설정합니다. 미리보기에서 **2 of 2 events recognized, 0 unsafe, 0 not matching**을 확인합니다.
3. **Apply declared relay profile**을 클릭한 다음 **Analyze Logs**를 클릭합니다. 실제 테스트에서 **2 of 2 log events parsed completely**가 표시됐습니다.
4. **Review Fields**에서 FortiGate 원문 `srcip`, `dstip`, `action`, `sessionid`와 비교하고 **Map Fields**에서 Stellar Cyber 7.0 매핑을 검토합니다.
5. **Create Parser → Run Final Test & Create Files**를 실행합니다. 영상의 로컬 최종 테스트는 성공했습니다. 실제 DP 설치·수신까지 검증된 것은 아닙니다.

## 별도 검증용 로그 — 다른 FortiGate Web Filter 이벤트

아래 한 줄은 **다른 Fortinet 공식 Web Filter 이벤트**가 실제 rsyslog로 전달된 출력입니다. 처음 두 건에 추가하지 말고 새로운 Auto Parser 분석에서 같은 `relay01` 설정으로 테스트하세요.

```text
<134>Oct 31 14:42:17 relay01 forwarder: date=2019-05-13 time=16:29:45 logid="0316013056" type="utm" subtype="webfilter" eventtype="ftgd_blk" level="warning" vd="vdom1" eventtime=1557790184975119738 policyid=1 sessionid=381780 srcip=10.1.100.11 srcport=44258 srcintf="port12" srcintfrole="undefined" dstip=185.244.31.158 dstport=80 dstintf="port11" dstintfrole="undefined" proto=6 service="HTTP" hostname="morrishittu.ddns.net" profile="test-webfilter" action="blocked" reqtype="direct" url="/" sentbyte=84 rcvdbyte=0 direction="outgoing" msg="URL belongs to a denied category in policy" method="domain" cat=26 catdesc="Malicious Websites" crscore=30 craction=4194304 crlevel="high"
```

실제 검증: 릴레이 헤더 **1/1 인식**, 이벤트 **1/1 완전 파싱**.

## 예상 결과

영상에서 실제 입력한 로그와 같은 원문을 문서에서 복사해 실행할 수 있습니다. `relay01`은 방화벽 제조사·장비명이 아니라 릴레이 호스트입니다. 운영망이나 실제 Stellar Cyber DP는 연결하지 않았습니다.

## 복구 방법

값이 누락되거나 릴레이가 인식되지 않으면 `relay01` 선언과 `<134>` Syslog 헤더를 확인하고, 미파싱 부분을 버리지 마세요. 실제 rsyslog 구성·원문 출처·별도 검증 내용은 [상세 시나리오](/ko/scenarios/relay-forwarder)에 있습니다.
