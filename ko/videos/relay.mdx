# 동영상 05 — 로그 릴레이를 거쳐 전달된 이벤트

이 영상은 2026년 10월 31일 공개 Parser Studio 웹 UI에서 직접 동작시키며 녹화했습니다. **영어 음성·화면 자막**이 포함되고, 아래의 로그를 그대로 넣으면 단계별로 따라 할 수 있습니다. 예제는 **합성된 교육용 RFC3164 릴레이 캡처**이며 실제 고객이나 제조사의 원본 로그가 아닙니다.

### 영상에서 실제 입력한 로그

```text
<134>Oct 31 11:30:00 relay01 forwarder: date=2026-10-31 time=11:30:00 type=traffic subtype=forward action=accept srcip=192.0.2.10 dstip=198.51.100.20 srcport=51520 dstport=443 proto=6 sessionid=4101 sentbyte=482
<134>Oct 31 11:31:05 relay01 forwarder: date=2026-10-31 time=11:31:05 type=traffic subtype=forward action=deny srcip=192.0.2.11 dstip=198.51.100.25 srcport=51521 dstport=22 proto=6 sessionid=4102 sentbyte=0
```

### 화면 순서

1. [Parser Studio](https://app.parser.xdr.ooo/)의 **Auto Parser**를 열고 **Manufacturer**에 `Training`, **Product**에 `Relay KV demo`를 입력합니다.
2. 위의 릴레이 전달 후 로그 두 줄을 모두 **Add Logs**에 붙여 넣습니다.
3. **Optional: declare Syslog forwarder hostnames**를 열고 `relay01`을 입력합니다. **Maximum declared hops**는 `1`로 설정합니다.
4. **Relay source preview**에서 **2 of 2 events recognized, 0 unsafe, 0 not matching a declared relay**를 확인하고 **Apply declared relay profile**을 클릭합니다.
5. **Analyze Logs**를 클릭해 **2 of 2 log events parsed completely**인지 확인합니다.
6. **Review Fields**와 **Map Fields**에서 이벤트의 실제 IP, 액션, 프로토콜, 세션 ID와 Stellar Cyber 7.0 매핑을 검토합니다.
7. **Create Parser**에서 **Run Final Test & Create Files**가 허용되면 실행한 다음 결과를 확인하고 다운로드합니다.
8. 별도 검증 로그 한 건을 동일한 릴레이 설정으로 재검증합니다. 이 영상은 실시간 Syslog 수신 또는 실제 Stellar Cyber DP 설치를 시연하지 않습니다.

## 예상 결과

2026년 10월 31일 공개 UI에서 동일한 로그를 분석한 결과 릴레이 헤더 **2/2 인식**, 이벤트 **2/2 완전 파싱**을 확인했습니다. 다른 제품이나 실운영 수집기에서도 동일하다고 단정하지 않습니다.

## 복구 방법

릴레이가 인식되지 않는다면 `<134>` 우선순위 헤더, `relay01` 이름, `forwarder:` 프로그램 레이블을 확인합니다. **Optional: mark a forwarded prefix or trailing suffix**는 고정 텍스트 위치 검토일 뿐 변수 타임스탬프를 처리하는 생성 규칙이 아닙니다.
