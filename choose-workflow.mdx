# Which path should you use?

The main product menu intentionally has **two parser creation choices**, not a collection of separate editors.

| Situation | Recommended approach | Guide |
| --- | --- | --- |
| You have sample logs and do not know their format | Start with Auto Parser | [Auto Parser](/workflows/auto-parser) |
| Logs are recognized but some fields or values are missing | Review the flagged records first | [Unknown log](/scenarios/unknown-log) |
| You have comma-separated values and a vendor field document | Review column names and delimiter | [CSV with a spec](/scenarios/csv-with-spec) |
| You have positional firewall CSV | Treat columns as positional until verified | [Positional CSV](/scenarios/panos-positional) |
| The result has fields but incorrect normalized destinations | Edit the mapping on the same workflow | [Map Fields](/workflows/map-fields) |
| A rule remains unresolved or needs careful external help | Use the manual ChatGPT-assisted path | [ChatGPT assistance](/workflows/chatgpt-assisted) |
| You need additional test events | Download the offline Python sender | [Test sender](/scenarios/test-sender) |
| You want to compare local experiments | Save and restore browser-local versions | [Local Versions](/scenarios/revisions) |

## Three decisions that prevent common mistakes

1. **What is one logical event?** A pasted text block can contain multiple records, or one multiline event. Check record boundaries before editing mappings.
2. **Do field names have evidence?** JSON/KV often carries keys; positional CSV generally needs a specification. Never invent vendor semantics based only on a plausible value.
3. **Is the entire sample accounted for?** A partial extraction from one event is not evidence that other lines succeeded.

Technical controls are under **Tools & Diagnostics**. They supplement the selected workflow; they are not a third parser creation method.
