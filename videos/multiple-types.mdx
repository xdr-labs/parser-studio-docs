## Walkthrough

1. Identify Fortinet / FortiGate as the source product and select Add Another Log Type.
2. Create Traffic and Threat source groups.
3. Paste two manufacturer-published traffic records and the web-filter and IPS samples.
4. Choose Analyze Logs and confirm that all four source events parse completely.
5. Review the Traffic and Threat field differences; the documented corresponding traffic and web-filter records share session ID 381780.
6. Inspect type and subtype values; do not invent unverified conditional routing rules.
7. Review Stellar Cyber 7.0 mappings and run the final four-event test before download.

## Expected review outcome

Four original Fortinet documentation log examples parse completely in one project. The final four-event test and package generation pass.

Do not treat successful source extraction or generated files as evidence of full vendor/firmware coverage, target import acceptance, or live Stellar Cyber deployment compatibility.

## Recovery path

For a different log shape, keep the original records and examine the highlighted source spans, following the [related workflow](/scenarios/mixed-events). Only apply additional parsing rules after different examples pass a separate regression test. Never delete failing events merely to obtain a passing total.

## Original log provenance

- [Fortinet Document Library: Sample logs by log type](https://docs.fortinet.com/document/fortigate/6.2.0/cookbook/986892/sample-logs-by-log-type)

The published traffic and web-filter records share a session ID. These example logs are not claimed to be from a physical appliance independently inspected in this video.
