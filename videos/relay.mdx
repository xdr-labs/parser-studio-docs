## Practice along with the video

This **synthetic training case** is not an official vendor log and not a recording of a live Syslog stream. It reproduces a valid RFC3164 relay wrapper around two sample security-event bodies, with separate holdout test data.

### Copy the exact recorded relay sample

```text
<134>Oct 31 11:30:00 relay01 forwarder: date=2026-10-31 time=11:30:00 type=traffic subtype=forward action=accept srcip=192.0.2.10 dstip=198.51.100.20 srcport=51520 dstport=443 proto=6 sessionid=4101 sentbyte=482
<134>Oct 31 11:31:05 relay01 forwarder: date=2026-10-31 time=11:31:05 type=traffic subtype=forward action=deny srcip=192.0.2.11 dstip=198.51.100.25 srcport=51521 dstport=22 proto=6 sessionid=4102 sentbyte=0
```

### Follow the on-screen steps

1. Open [Parser Studio](https://app.parser.xdr.ooo/), choose **Auto Parser**, enter **Manufacturer: Training** and **Product: Relay KV demo**, then paste both complete wrapped log lines.
2. Expand **Optional: declare Syslog forwarder hostnames**, type `relay01`, and set **Maximum declared hops** to `1`. Verify the preview shows **2 of 2 events recognized, 0 unsafe, 0 not matching a declared relay**.
3. Click **Apply declared relay profile**, then **Analyze Logs**. The October 31 public UI returned **2 of 2 log events parsed completely** for this exact fixture.
4. Inspect **Review Fields** for `srcip`, `dstip`, `action`, `proto`, and `sessionid`. Continue through **Map Fields** and review proposed Stellar Cyber 7.0 names and types.
5. Proceed to **Create Parser** and run **Run Final Test & Create Files** only when enabled and source coverage is complete. Download the generated draft if its final test passes.
6. Re-run a separate validation with `05-relay-holdout.log`. No live relay transport or target import is demonstrated.

## Expected review outcome

The demonstrated browser run confirms two declared relay envelopes and two fully extracted events, with no discarded source record. A parser package is a local artifact; successful production receive and native runtime compatibility remain **not verified**.

## Recovery path

If the preview recognizes fewer than two relay headers, check the full `<134>Oct 31 ... relay01 forwarder:` prefixes and the exact declared hostname. Do not try to remove variable Syslog timestamps by the **Optional: mark a forwarded prefix or trailing suffix** control: that is a literal boundary review, not a generated parser rule.
