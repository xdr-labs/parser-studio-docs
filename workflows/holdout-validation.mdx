# Test a proposed fix on different events

When ChatGPT suggests a field extraction or mapping change, **a solution that fits only the original example is not sufficient**. Test it on a few other messages from the same source.

## How to prepare different examples

Suppose the first event was:

```text
action=allow src=192.0.2.10 reason="policy permitted"
```

For additional test logs, use records with different values or optional fields:

```text
action=deny src=192.0.2.11 reason="policy blocked"
action=allow src=192.0.2.12 reason="web traffic" user="demo user"
```

These examples are fictional. Use legitimate fresh examples from the relevant product when validating a real parser and keep private information in the browser.

## Which buttons do I click?

1. In **ChatGPT Assisted Parser**, first use **Check ChatGPT Result**.
2. If the proposal needs further testing, paste the new examples under **Additional ChatGPT test logs**.
3. Check **Confirm test examples are different** only when those records were not used to develop the candidate fix.
4. Run the available comparison and inspect the result.
5. Check **Approve tested ChatGPT fix** only if all original and additional events behave correctly.

Some unchanged, already-supported recipes may not require a changed-rule comparison. Follow the result shown by Parser Studio.

## What if the test fails?

Do **not** approve the candidate. Inspect the field that changed, provide ChatGPT with a clearer *masked* explanation, and submit a revised supported response through the same review process.

<Note>
  A successful additional-sample test increases confidence for the records you examined. It does not prove that every other message from that product will work.
</Note>
