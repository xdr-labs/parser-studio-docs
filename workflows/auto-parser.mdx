# Auto Parser: the default workflow

Use **Auto Parser** for most new log types. It is designed to start from data rather than parser syntax.

## Step 1 — Add Logs

1. Copy a few complete events from the same log source or upload a bounded text sample.
2. Preserve the original delimiters, quotes, leading Syslog headers and line endings wherever possible.
3. Click **Analyze Logs** and inspect the detected families and the number of logical events.
4. Review incomplete, malformed or uncertain events; do not assume the displayed family label proves full extraction.
5. For CSV, complete **Review CSV column names** and explicitly approve the chosen schema if the control appears.

A single preview does not establish that records with different firmware, settings or forwarding prefixes will behave identically.

## Step 2 — Review Fields

1. Select **Review Fields** once the sample is eligible to continue.
2. Switch between events and compare raw text to extracted names and values.
3. Confirm no significant suffix, leading header or extra event was silently omitted.
4. If an event needs review, follow the highlighted area and proposed repair rather than forcing a passing status.

[Review fields in detail](/workflows/review-fields).

## Step 3 — Map Fields

1. Select **Map Fields**.
2. Confirm each source field's destination, type and visible sample values.
3. Look for duplicate targets, type mismatches and unsupported destinations.
4. Apply only verified suggestions and correct individual exceptions.

[Mapping guide](/workflows/map-fields).

## Step 4 — Create Parser

1. Continue to **Create Parser**.
2. Check the event counts and any blockers.
3. Select **Create Parser Files**.
4. Download the verified output pair. Keep the output with the exact reviewed input and its mapping assumptions.

[Download and verification](/workflows/create-and-download).

## When to open advanced tools

**Tools & Diagnostics** is useful for inspecting an existing parser, reviewing unusual multiline boundaries, understanding repeat patterns or examining technical evidence. If you are a first-time user, complete the main guided stages before opening advanced controls.

## A safe completion checklist

- Every source event is represented in the review.
- Important fields are extracted with correct values and boundaries.
- Column names and normalized destinations have documented meanings.
- The final test reports no blocking errors.
- Output files are downloaded after the product's integrity checks.

If any item is missing, treat the result as a review draft and use [troubleshooting](/reference/troubleshooting).
